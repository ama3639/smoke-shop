# راه‌اندازی و نگهداری نسخه پایه

نسخه: 0.2.0 · تاریخ: 2026-10-09

## نصب در ویندوز

Python 3.12 یا جدیدتر و Node.js 22 یا جدیدتر (ترجیحاً LTS) نصب باشد. اجرای محلی به Docker، Redis، کلید AI یا سرویس پرداخت نیاز ندارد.

```powershell
Set-Location D:\Smokeshop
py -3.12 scripts/setup.py
py -3.12 scripts/dev.py
```

setup محیط مجازی Python و وابستگی‌های قفل‌شده را نصب می‌کند، migration و نقش‌ها را اعمال می‌کند و شش کالای نمونه فقط‌کاتالوگ می‌سازد. اجرای مجدد محصولات موجود را بازنویسی نمی‌کند و فروش را فعال نمی‌کند. نصب به PyPI و npm نیاز دارد.

dev دو سرویس را اجرا می‌کند. فروشگاه در `http://localhost:3000` و مدیریت در `http://localhost:8000/admin/` است. Ctrl+C سرویس‌های همین اجرا را متوقف می‌کند. پورت‌های 3000 و 8000 باید آزاد باشند. بک‌اند با `--noreload` اجرا می‌شود؛ بعد از تغییر کد Python این اسکریپت را دوباره اجرا کنید. فرانت‌اند تغییرات را خودکار اعمال می‌کند.

ساخت مدیر (یک‌بار؛ رمز تعاملی و بدون ذخیره در Git):

```powershell
.\backend\.venv\Scripts\python.exe backend\manage.py createsuperuser
```

برای کاربران ادمین از Users گزینه Staff و گروه مناسب را تعیین کنید. `Catalog editor` مشخصات و موجودی را مدیریت می‌کند؛ تأیید حقوقی و فعال‌سازی عرضه برای `Legal reviewer` و superuser است.

## کاتالوگ و عرضه

در ادمین دسته، کالا، تصویر JPG/PNG/WebP، مدل، رابطه سازگاری و شعبه را ثبت کنید. وضعیت پیش‌فرض کالا `REVIEW_REQUIRED` است و در API عمومی دیده نمی‌شود. `CATALOG_ONLY` کاتالوگ بدون خرید است. `IN_PERSON_ONLY` معرفی عرضه حضوری است؛ `BLOCKED` و کالاهای غیرفعال از API عمومی حذف می‌شوند.

نمونه‌ها داده واقعی نیستند. پیش از نمایش عمومی، `DEMO-*` را غیرفعال یا با اطلاعات واقعی جایگزین کنید. SVGها تصویر نمونه‌اند؛ تصویر واقعی از ادمین قابل بارگذاری است. رابطه سازگاری نمونه «آزمایشی» است و منبع واقعی ندارد.

خرید به این شروط نیاز دارد: `APPROVED_ONLINE` با مرجع کتبی حقوقی، فعال‌بودن فروش دسته، flag با کلید `cart` و قیمت/موجودی معتبر. همه در API بررسی می‌شوند. تأیید سن فقط کنترل کمکی است.

flag با کلید `order_requests` ثبت **درخواست سفارش بدون پرداخت** را فعال می‌کند. قبل از فعال‌کردن، فرآیند بررسی اپراتور و انقضای رزرو را تعیین کنید. درخواست موجودی را رزرو می‌کند، مبلغ و عنوان را از سرور snapshot می‌گیرد و با کلید یکتا از تکرار جلوگیری می‌کند. هیچ درگاه، تأیید پرداخت، ارسال یا تبدیل خودکار به سفارش قطعی وجود ندارد.

لغو رزرو توسط اپراتور و آزادسازی موجودی دقیقاً یک‌بار:

```powershell
.\backend\.venv\Scripts\python.exe backend\manage.py cancel_order UUID-OF-ORDER
```

سفارش‌ها، دفتر موجودی و Audit Log از پنل فقط قابل مشاهده‌اند. تغییر قیمت، موجودی، وضعیت حقوقی، دسته و flag ثبت می‌شود. رزروها خودکار منقضی نمی‌شوند؛ اپراتور باید درخواست‌های معلق را بررسی و در صورت نیاز لغو کند. API نشانی یا تلفن مشتری نمی‌گیرد؛ پیگیری مهمان فقط با نشست همان مرورگر ممکن است.

## نگهداری و به‌روزرسانی

سرویس‌ها را متوقف کنید و پیش از migration از داده‌ها backup بگیرید. هنگام توقف از `backend/db.sqlite3`، `backend/media/` و `backend/.local-secret` نسخه پشتیبان امن تهیه کنید. این فایل‌ها نباید وارد Git شوند. بازیابی backup را روی محیط مجزا آزمایش کنید.

```powershell
Set-Location D:\Smokeshop
git status --short
git pull --ff-only origin main
py -3.12 scripts/setup.py
py -3.12 scripts/dev.py
```

`--ff-only` در تاریخچه واگرا متوقف می‌شود؛ تغییرات محلی را پیش از pull حفظ کنید. نصب مجدد داده‌ها را حذف نمی‌کند.

برای پاک‌سازی نشست‌های منقضی، `backend/manage.py clearsessions` را با Python محیط مجازی اجرا کنید. این فرمان سبدها و سفارش‌ها را حذف نمی‌کند؛ سیاست نگهداری آن‌ها پیش از عرضه عمومی باید تعیین و اجرا شود.

## تست و build

```powershell
.\backend\.venv\Scripts\python.exe backend\manage.py test shop
Set-Location frontend
npm run typecheck
npm run build
npx playwright install chromium
npm run test:e2e
```

E2E از بک‌اند 8010، فرانت‌اند 3010 و دیتابیس موقت استفاده می‌کند؛ flag آزمون وارد داده‌های توسعه نمی‌شود. دو تست هم‌زمانی در PostgreSQL اجرا و در SQLite با دلیل مشخص skip می‌شوند. CI تست PostgreSQL، build و مرورگر دسکتاپ/موبایل دارد.

## تنظیمات و تولید

تنظیمات Django از متغیرهای فرایند خوانده می‌شوند؛ کپی `.env` به‌تنهایی آن‌ها را اعمال نمی‌کند. پیش‌فرض‌ها برای توسعه کافی‌اند.

| متغیر | کاربرد |
| --- | --- |
| `BACKEND_URL` | آدرس داخلی بک‌اند Next؛ پیش‌فرض `http://127.0.0.1:8000`؛ هنگام build و start یکسان باشد |
| `DJANGO_DEBUG` | پیش‌فرض `1`؛ تولید `0` |
| `DJANGO_SECRET_KEY` | محرمانه و الزامی در تولید؛ توسعه فایل کلید محلی می‌سازد |
| `DJANGO_ALLOWED_HOSTS` | میزبان‌های دقیق Django، جداشده با کاما |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | مبدأ دقیق HTTPS فروشگاه و ادمین، جداشده با کاما |
| `DATABASE_URL` | اتصال PostgreSQL؛ در تولید الزامی |
| `DB_SSLMODE` | پیش‌فرض `require`؛ فقط PostgreSQL محلی بدون TLS: `disable` |

SQLite برای توسعه تک‌کاربره است. تولید به PostgreSQL و TLS معتبر نیاز دارد. اجرای تولید: `gunicorn config.wsgi:application` در backend و `npm run build` سپس `npm start` در frontend؛ ابتدا migration و `collectstatic --noinput` اجرا شوند. reverse proxy باید TLS را terminate کند، `/admin/` و `/static/` را به Django/staticfiles و `/media/` را به فضای رسانه پایدار هدایت کند، مسیرهای فروشگاه را به Next بفرستد و headerهای forwarded را از کاربر نپذیرد. بک‌اند باید داخلی بماند.

این نسخه برای توسعه و نمایش پایه است. احراز سن قابل اتکا، 2FA ادمین، پرداخت، آدرس و ارسال، انقضای خودکار رزرو، rate limiting، مانیتورینگ و ممیزی امنیتی تولید هنوز پیاده نشده‌اند. AI سلامت، RAG و موشن سه‌بعدی اسکرول در این نسخه وجود ندارند. عرضه عمومی به تکمیل این موارد و تأییدهای واقعی نیاز دارد.
